# Article Draft（文章草稿生成 Skill）

## 啟動前必讀

1. `references/部落格排版規範.md`
2. `references/驗光師文案法律須知.md`

## 草稿生成流程

### Step 1 — 素材準備
- 若有知識卡片：讀取 `obsidian-vault/04-知識卡片/` 相關卡片
- 若有歷史文章：掃描 `skills/optometry-writer/data/blog-index.json` 找內部連結

### Step 2 — C.A.S.T. 結構撰寫
- **C** Connect：5 秒鉤子開場，融入真實店內情境
- **A** Amplify：對焦隱憂，不製造恐慌
- **S** Solve：FABE 專業解方，白話文呈現
- **T** Transform：務實收尾，帶出驗光所行動

> **T 步驟關鍵原則（微型 CTA）**：
> 不要只說「歡迎預約」，要給一個**零摩擦的低門檻入口**。
> 最強的 CTA 不是叫人買東西，而是叫人做一件「不花錢、不花時間、不需要決定」的事。
> 範例：「免費調整鏡架 / 免費洗眼鏡 / LINE 先問不用到店 / 帶舊眼鏡來評估就好」
> 這類微型 CTA 的轉換力，實測比「立即預約」高出約 15-20 分（Shadow QA 壓測驗證）。

### Step 3 — 合規審查
禁用詞自動替換：
| 禁用 | 替換 |
|------|------|
| 治療/治癒 | 發展追蹤/光學方案 |
| 診所 | 驗光所/店裡 |
| 患者 | 客人/小朋友 |
| 醫生 | 驗光師/大叔 |

### Step 4 — 標題生成
產出 3 組標題（在地權威型、AI 友善型、數字佐證型）+ 終極破表標題（≥90 分）

### Step 5 — 配圖咒語
生成 AI 繪圖英文 Prompt（鎖定目鏡大叔人設前綴）

## 字數目標

| 類型 | 字數 |
|------|------|
| 一般衛教文 | 1,000–1,500 字 |
| 深度教學 + FAQ | 1,500–2,000 字 |
| 超競爭主題 | 2,500 字以上 |

## 發布前壓測（上戰場前必跑）

草稿完成後、HTML 完稿前，**必須跑以下兩道關卡**：

### 關卡 A：Shadow QA 紅隊審查
執行 `.agents/workflows/shadow-qa.md`，三個審查官依序輸出：
1. **衛生局稽查員**：法規紅線掃描（禁詞、醫療效果宣稱、數字可查驗性）
2. **公關危機顧問**：潛在輿論炸彈偵測
3. **惡意競爭對手**：找可被攻擊的最脆弱論點

通過 → 繼續；有紅燈 → 先修再進 HTML 完稿。

### 關卡 B：家長模擬器快版（取 3 個人格）
執行 `.agents/workflows/parent-simulator.md`，選最相關的 3 個家長人格反饋：
- 文章讀完，**有沒有讓他知道下一步要做什麼？**
- 如果他看完不知道怎麼行動 → T 步驟（Transform）需要加微型 CTA

> **實戰驗證**（2026-04-12）：情感文《帶孩子、帶長輩配眼鏡的爸爸》跑完家長模擬器後，
> 補上「免費洗眼鏡/調鏡架/評估舊眼鏡」微型 CTA，分數從 85 → 98，低門檻入口是關鍵。

## 草稿完成後的自動輸出

草稿產出後，**不需要等大叔提醒**，自動輸出：

1. **FB 手機版** → `content-planning/{文章名稱}-FB版.txt`
   - 純文字、一句一行、蔡格尼節奏、350-500字、子標題用 `◾`
2. **Threads 串文版** → `content-planning/{文章名稱}-Threads版.txt`
   - 3-5 則、每則 ≤500 字元、標示 `【1/N】`、最後一則加 hashtag

HTML 完稿（含 Schema + Canonical）交給 `optometry-writer` 處理。
