## 1. 專案核心願景

建立一套以「視光知識物件、臨床經驗、人格信任」為核心的內容與產品系統，讓同一份資料可被網站、搜尋引擎、AI 問答、工具、視力家家簿、LINE、App 與門市服務共同使用。

**本專案的核心原則是**：
> **底層像資料庫一樣完整，前台像一位懂家長、會陪伴、會引導的驗光師。**

## 2. 臨床資料整理器 (Clinical Data Organizer) 與視力家家簿 5 大安全硬規則

### 2.1 嚴禁假精準與簡化醫療判定
1. **工具定位與流程**：
   - 流程：`輸入資料 ➔ 是否同儀器 ➔ 差值是否可直接比較 ➔ 呈現原始變化 ➔ 說明數學換算限制 ➔ 找出缺少資料 ➔ 產生追蹤清單 ➔ 儲存時間線`。
   - 所有前台工具**只做資料整理與可比較性點檢，不做醫療判定**。
2. **同台儀器 vs 不同儀器之可比較性降級**：
   - 當「是否同台儀器 = 否」時，主要評估結論標示：`因兩次使用的儀器或測量條件不同，直接相減後的差值可能同時包含儀器差異，不宜單獨解讀為實際眼軸變化。`
   - 選「同台儀器 = 是」時補充：`使用同一台儀器能提高可比較性，但仍需確認眼別、測量品質與原始報告。`
3. **時間差值與短期風險控制 (months < 3)**：
   - 若追蹤月數 `< 3` 個月，系統提示：`追蹤間隔較短（小於 3 個月），年化換算容易放大測量波動，建議以原始差值為主。` 且不加粗年化數值。
4. **防呆範圍提示非臨床正常區間**：
   - 提示語：`輸入值超出本工具可接受的格式範圍，請確認是否輸入錯誤或單位不正確。`
5. **原始報告欄位引導**：
   - 欄位：`手邊是否有原始檢查報告或完整數據紀錄？`
   - 選項：`有原始報告或完整紀錄` / `只有部分數字或口頭資訊`。
   - 當選擇無完整紀錄時，列出 5 項具體缺少欄位（日期/儀器型號、左右眼別/原始眼軸、散瞳狀態、屈光度數、曲率/配戴方式）。
6. **視力家家簿 MVP (Timeline Vault)**：
   - 支援建立孩子個人檔案，分別儲存右眼 (OD) 與左眼 (OS) 之雙眼獨立數據。
   - 自動將整理紀錄壓入時間線軸 (Timeline Axis)，形成長期發育軌跡備查。

## 3. 前台品牌與 RWD 熟齡無障礙規範

1. **人先出現，知識後出現**：展示親切的驗光師陪伴形象。
2. **前台品牌**：`目鏡大叔`，輔助標語 `陪你看懂視力這件事`。
3. **六大情境卡片獨立 Journey 分流**：包含近視增加、報告解讀、控制選擇、配鏡不適、電腦疲勞、長輩多焦點 6 大獨立處理分流。
4. **DOM 安全性與 RWD 響應式**：
   - 使用 `@media (max-width: 768px)` 解決手機版導航與表單爆版問題。
   - JavaScript 渲染採用 `textContent` 與元素建構，避免 DOM 注入風險。
