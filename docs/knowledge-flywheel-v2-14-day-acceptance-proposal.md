## 每一題都要走的檢查

1. **Source**：來源可回讀；保存 DOI/PMID/日期；僅看摘要時有標籤。
2. **Evidence**：能以原文核對樣本、單位、效果量；觀察、假說與指引分明。
3. **Zettelkasten**：至少一張「完整句的原子命題」，與至少一張既有卡連成有意義的關係；若重複，更新舊卡而不是新建。
4. **KDF**：Candidate vs Validated vs Decision Rule 狀態正確，無人工 Gate 的自動提升視為 fail。
5. **Application**：文章或教材中的重要段落能回指來源與論點；公開 URL 只在實際發布後補。
6. **Feedback**：至少紀錄一個後續真實問題／誤解／修訂建議；不得把互動當醫學證據。
7. **Integrity**：GitHub 變更可稽核、路徑正確、無重複 ID／孤島連結／來源 URL 失效。
8. **Privacy**：沒有病患辨識資料、內部商業祕密或未經允許的私人觀察進 public。
9. **Sync**：雲端確認與本機 Obsidian 搜尋是兩個獨立驗收，不可只看 GitHub commit。

## 停止條件 / Fail-fast

- 無法確認來源的研究被轉成正式卡。
- 公開文章將相關性寫成因果或把短期指標寫成長期臨床效果。
- 兩套 Repo 同時被自動當成母本寫入，引發版本分叉。
- 私有資料被提交公開。
- KDF Bridge／同步未驗收，卻宣稱自動閉環已成功。
