# Hermes Shared Brain Runtime

Hermes is the orchestration and parallel-execution runtime for this repository.

## Startup

Before substantial work:

1. Read `SOUL.md` and `USER.md`.
2. Read today's and yesterday's `memory/YYYY-MM-DD.md` when present.
3. Read `MEMORY.md` only in a direct private session with the user.
4. Read `LOCAL-ROLE.md` to understand which computer is active.
5. Inspect `git status --short --branch` before sync or implementation.

## Canonical Memory

- Capture: `Inbox/`
- Working memory: `memory/YYYY-MM-DD.md`
- Durable decisions: `MEMORY.md`
- Durable knowledge: `obsidian-vault/`
- Skills and workflows: `.agents/skills/` and `.agents/workflows/`

Hermes internal memory is not the cross-computer source of truth. Anything that must survive a session or move to the other computer must be written into the repository.

## Role

Use Hermes for:

- multi-step execution
- parallel research or processing
- work queues and delegated subtasks
- repeatable operations
- preparing explicit handoffs

Claude Code and Codex remain the final writers for architecture, core protocols, and long-term memory.

## Handoff

Use `HANDOFF-PROTOCOL.md`. Every handoff must name the task, state, next owner, expected output, blockers, and paths.

## Sync

Use `scripts/sync-brain.ps1 -Mode Status` to inspect state. Do not pull or push over uncommitted work.
