# 備課研究到品牌文章：驗證腳本模板

這份筆記是「備課研究到品牌文章」工作流的品管層。  
前面已經完成 metadata schema 與檔名/資料夾規則；這一步把「跑完後怎麼驗收」固定下來。

對應 Hermes Skill：

```text
lesson-prep-research-to-brand-article
```

對應腳本模板：

```text
C:\Users\torna_3j3fz9h\AppData\Local\hermes\skills\research\lesson-prep-research-to-brand-article\scripts\validate_asset_pack.py
```

---

## 1. 驗證目標

每次完成一個主題資產包後，至少要確認：

- 檔案是否存在於正確資料夾。
- 檔名是否符合 [[備課研究到品牌文章-檔名與資料夾規則]]。
- frontmatter 是否存在。
- `workflow: lesson-prep-research-to-brand-article` 是否存在。
- `asset_type` 或 `type` 是否與資產類型一致。
- 研究工作流是否保留研究問題、搜尋策略、PICO/PECO/PICo、文獻、證據、過度宣稱。
- 專業文章是否保留來源、DOI、過度宣稱防火牆。
- 評審報告是否保留 review_score、evidence_score、overclaiming_score、publish_ready_red_flags。
- 聲紋版是否連到聲紋後安全複審。
- 聲紋後安全複審是否保留來源與風險提醒。

---

## 2. 驗證模式

### 2.1 minimal

最小完整包，適合還沒做 MOC / 知識卡拆分時：

```text
研究工作流筆記
專業文章草稿
文章評審報告
```

### 2.2 brand

只驗證聲紋與安全複審：

```text
目鏡大叔品牌版
聲紋後安全複審
```

### 2.3 complete

完整資產包：

```text
研究工作流筆記
MOC 主題索引
證據地圖
過度宣稱防火牆
教學設計卡
專業文章草稿
文章評審報告
目鏡大叔品牌版
聲紋後安全複審
```

## 4. Hermes 執行規範

若是任務完成後的驗證，優先使用 OS-safe temporary script：

```text
C:\Users\TORNA_~1\AppData\Local\Temp\hermes-verify-*.py
```

原則：

1. 從 skill 內的 `validate_asset_pack.py` 複製或參考邏輯。
2. 建立 `hermes-verify-` 前綴的臨時腳本。
3. 執行檢查。
4. 刪除臨時腳本。
5. 回報時明確說這是 ad-hoc verification，不是正式 test suite green。

---

## 5. 通過訊號

成功時應輸出：

```text
AD_HOC_VERIFY_PASS
```

失敗時應輸出：

```text
AD_HOC_VERIFY_FAIL
```

並列出：

- 缺少哪個檔案。
- 哪個 frontmatter 不完整。
- 哪個 asset_type 不一致。
- 哪個內容錨點缺失。
- 哪個 publish-ready 條件不完整。

## 6. 目前限制

這份腳本模板是工作流品管的第一版，仍然是 ad-hoc verification，不是正式測試框架。

目前主要檢查：

- 檔案存在。
- frontmatter 存在。
- workflow 錨點存在。
- asset_type / type 基本一致。
- 內容錨點存在。
