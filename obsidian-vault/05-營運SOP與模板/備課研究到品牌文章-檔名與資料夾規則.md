# 備課研究到品牌文章：檔名與資料夾規則

這份規則是「備課研究到品牌文章」工作流的第二個自動化基礎層。  
前一步已固定 [[備課研究到品牌文章-metadata-schema]]，這一步固定每一類產出應該放在哪裡、怎麼命名、怎麼互相連結。

對應 Hermes Skill：

```text
lesson-prep-research-to-brand-article
```

---

## 1. 命名原則

### 1.1 日期

所有具時間性的產出使用：

```text
YYYY-MM-DD
```

例如：

```text
2026-07-08
```

### 1.2 主題 slug

Obsidian 筆記可以使用可讀中文 slug，但要避免太長。

建議：

```text
兒童近視控制不是保證不加深
散瞳驗光與家長溝通
AI驗光所內容策略
```

避免：

```text
final
new
v2
最新版
未整理
```

### 1.3 禁用字元

檔名不可包含：

```text
? ？ ! ！ : ： / \ | * < > "
```

| 資產類型 | 資料夾 | 用途 |

## 4. 標準連結規則

### 4.1 研究工作流筆記應連到

- MOC 主題索引
- 證據地圖
- 過度宣稱防火牆
- 教學設計卡
- 專業文章草稿
- 文章評審報告
- 目鏡大叔品牌版
- 聲紋後安全複審

### 4.2 所有資產都應回連

- 研究工作流筆記
- MOC 主題索引

### 4.3 專業文章草稿應連到

- 研究工作流筆記
- 證據地圖
- 過度宣稱防火牆

### 4.4 品牌版文章應連到

- 專業文章草稿
- 文章評審報告
- 聲紋後安全複審

---

## 5. 碰撞處理原則

如果檔案已存在：

1. 不可靜默覆蓋。
2. 先讀取既有檔案。
3. 若是同一主題的 canonical asset，優先保留原檔並追加新段落或更新 metadata。
4. 若語意不明，先詢問。
5. 只有測試檔或草稿允許加 `-draft-<timestamp>`。

---

## 6. 一次完整產出的預期檔案群

以 `<slug>` 為主題名，標準完整輸出會形成：

```text
05-營運SOP與模板/YYYY-MM-DD-<slug>-研究工作流.md
01-專家與MOC/MOC-<slug>.md
04-知識卡片/YYYY-MM-DD-<slug>-證據地圖.md
04-知識卡片/YYYY-MM-DD-<slug>-過度宣稱防火牆.md
04-知識卡片/YYYY-MM-DD-<slug>-教學設計卡.md
04-知識卡片/文獻卡-<source-slug>.md
10-歷史文章智庫/YYYY-MM-DD-<slug>-專業文章草稿.md
10-歷史文章智庫/文章評審報告-<slug>.md
10-歷史文章智庫/YYYY-MM-DD-<slug>-目鏡大叔品牌版.md
05-營運SOP與模板/聲紋後安全複審-<slug>.md
```

不是每次都必須產出所有檔案；但如果標記為完整資產包，至少要有：

- 研究工作流筆記
- 專業文章草稿
- 文章評審報告
- 若做聲紋版，必須有聲紋後安全複審

## 7. 與自動化 pipeline 的關係

這份規則完成後，下一階段已建立：

```text
驗證腳本模板 → [[備課研究到品牌文章-驗證腳本模板]]
```

再下一階段已接續處理：

```text
可重跑的 pipeline script → [[備課研究到品牌文章-pipeline-script]]
```

驗證腳本要能根據本規則檢查：

- 檔案是否存在於正確資料夾
- 檔名是否符合 asset_type
- frontmatter 的 asset_type 是否與檔名一致
- 必要 wikilink 是否存在
- publish-ready 是否有評審與紅旗檢查

---

## 8. Ad-hoc verification 應檢查錨點

每次修改本規則，至少檢查：

- workflow: lesson-prep-research-to-brand-article
- 標準資料夾對照存在
- 標準檔名規則存在
- 標準連結規則存在
- 碰撞處理原則存在
- 完整輸出檔案群存在
- 下一階段為驗證腳本模板
- 與一鍵工作流、metadata schema 互相連結
