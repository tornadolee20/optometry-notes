# Claude Code 的 11 個底層架構秘密

> **來源**：影片《剛剛 Claude Code 源碼泄露！我扒出了 11 個隱藏秘密》逐字稿
> **背景**：Claude Code 2.1.88 發布時未排除 Source Map，導致 50 萬行 React Ink 前端與底層架構代碼完全還原。

## 核心架構六層次
由上至下：CLI 介面層 ➡️ Agent 循環引擎 ➡️ 工具系統 (MCP) ➡️ 記憶與上下文壓縮 ➡️ 權限安全系統。

---
 
### 1. Agent 循環 (ReAct 機制)
最核心就是一個 `while(true)` 無限循環。
- 順序：上下文壓縮 ➡️ 呼叫大模型 ➡️ 解析 `tool_use` ➡️ 執行工具 ➡️ 將結果追加對話歷史 ➡️ 進入下一輪。一直到沒有工具呼叫才停止。

### 2. 按需加載的工具設計 (Fail-closed)
- 內建 40+ 工具。
- 不會把工具細節全塞進 System Prompt，而是先給「精簡清單」，模型點名後才載入完整定義（極度節省 Token）。
- 預設「失敗時關閉 (Fail-closed)」，預設禁止併發或修改。

### 3. 讀寫分離的並行機制 (Max 10)
- **讀取 (Read)**：可以最多 10 個工具同時並行。
- **寫入 (Write)**：遇到寫操作，必須排隊等前面的讀取完成。
- **批次生效**：寫入修改不是立刻生效，是在一個批次跑完後才統一應用，避免中途衝突。

### 4. 提示詞的緩存分裂 (Prompt Cache)
- **靜態部分 (上半部)**：全球百萬用戶共享同一份 Cache，極大幅降低 API 成本。
- **動態部分 (下半部)**：如時間、本地代碼倉庫狀態等，各用戶獨立。

### 5. 放棄 RAG，擁抱純 Grep (啟發性極高)
**Claude Code 壓根不用業界流行的 RAG (檢索增強生成)**。
- 它找資料全靠樸素的純文字搜尋 (`grep`)。
- **原廠洞察**：讓 AI 自己決定要搜什麼字眼，效果「遠遠大於 RAG」。
- **優勢**：沒有索引過期問題、不用維護向量資料庫、工程複雜度大幅降低。

### 6. 三層自癒記憶架構 (Self-Healing Memory)
1. **目錄層 (`MEMORY.md`)**：最多 200 行 / 25KB，只存路徑指標，超過就砍。
2. **話題偏好層**：新對話時用小模型 (Sonnet) 挑 5 個載入。**核心原則：絕對不記客觀事實 / 代碼（那些去源碼讀），只記使用者的「偏好」跟「踩過的坑」**，從源頭消滅幻覺衝突。
3. **歷史對話層**：存為特定格式，需要時用 Grep 抓取。

### 7. 五級上下文壓縮 (Token 防禦戰)
應對 Token 快速膨脹的 5 道防線：
1. **剪裁**：舊的工具結果只留 JSON 結構不留內容。
2. **微壓縮**：大體積結果卸載到緩存。
3. **上下文折疊**：對話折疊成摘要。
4. **自動壓縮**：超載閾值立刻全量壓縮。
5. **應急壓縮**：API 彈錯時的強制措施。
- 附帶**斷路器**：連續失敗三次就停機，防止燒錢。

### 8. 影子安全審查 (yoloClassifier)
即便打開 YOLO（跳過確認）模式，背後仍有一個影子 AI 在審查指令，內含至少 20 項 Bash 安全規則。

### 9. 未來藍圖曝光：KAIROS 與 AutoDream (最震撼啟發)
- **KAIROS 模式**：長期助手，可 24 小時駐留執行。
- **AutoDream (自動做夢功能)**：✨ 白天收集筆記與雜訊，夜間系統自動在背景整理記憶、重新收斂邏輯！這正是「系統體檢工作流」的終極型態。

### 10. 反蒸餾與臥底模式
- 故意灌假數據給錄製 API 流量的對手。
- 內部員工發 PR 時隱藏模型真實代號。

## 🎯 大叔的三 AI 體系實踐與校準

從這份外洩報告，我們可以高度確信我們走在正確的道路上：
1. 我們剛剛寫的 **`search_obsidian` MCP 伺服器** 使用 Regex/Grep 取代向量化，路線與 Anthropic 原廠完全一致。
2. **AutoDream 理念**：印證了我們稍早構思的「自動矛盾收斂引擎」非常有實作價值，這將是接下來的開發重點。
3. **讀寫分離**：提醒我們在設計大叔的自動寫稿機時，未來若有大量文件，必須確保「先並行閱讀論文，最後再批次寫入卡片」。
