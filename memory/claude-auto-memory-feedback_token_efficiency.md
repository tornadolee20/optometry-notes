name: Token 效率天條
description: 系統操作必須優先選擇最省 token 的方式，效率優化是最高準則
type: feedback
---

永遠選擇最省 token 的操作方式，這是天條，不得妥協。

**Why:** 大叔明確指示，token 效率是本系統的最高優先級（稱為「天條」）。每次操作的固定啟動成本（CLAUDE.md + MEMORY.md 等約 3,000–5,000 tokens）不可浪費。

**How to apply:**
- 素材少（1–2 篇）→ 即時處理
- 素材多（5 篇以上）→ 堆進 `Inbox/raw/`，批次一次處理
- 避免重複載入相同上下文
- 能用 Grep/Glob 精準搜尋就不用 Agent 全掃
- 能讀局部就不讀整份檔案
- 有選擇時，永遠挑 token 消耗更少的路徑
- 回覆要極度簡潔，不解釋、不重述、不鋪陳
- 只有兩種情況才說清楚：① 需要大叔決策 ② 值得寫進知識庫的洞見
