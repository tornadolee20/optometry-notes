### LINE 作為核心樞紐

**關鍵洞察：LINE 不是功能，是接頭。**

```
LINE Official Account（Hub）
        │
   Rich Menu 四格
   ┌────┼────┐
   │    │    │
 [評論] [預約] [文章] [會員]
   │    │    │    │
   ↓    ↓    ↓    ↓
各自獨立系統，互不影響原有架構
```

**三個系統串接方式：**
- 評論系統 → MYOWNREVIEWS
- 預約系統 → Google表單 或 現成工具（先不自建）
- 部落格 → uncle-glasses.net

每個系統對 LINE 來說只是一個網址，完全鬆耦合。

---

### 讓飛輪真正轉起來的技術關鍵：LIFF

**LIFF（LINE Front-end Framework）= 身份自動識別**

```
客人從 LINE 點任何連結
        ↓
LIFF 自動傳遞 LINE User ID（不需登入）
        ↓
每個系統都認識「這個人是誰」
        ↓
三個獨立系統用 line_user_id 自然串聯
```

**各系統需要加的欄位：**
- MYOWNREVIEWS → `line_user_id`（一個 migration）
- 預約系統 → `line_user_id`
- 部落格 → 可選（文章閱讀行為追蹤）

`line_user_id` 是整個飛輪的隱形主軸。

### 在店內的實際操作流程

```
服務完成
    ↓
店員口頭邀請（只問滿意的客人）← 人工篩選，天然差評過濾
    ↓
客人掃 QR → 加入 LINE 官方帳號
    ↓
歡迎訊息直接帶評論連結（趁衝動最強的那一刻）
    ↓
MYOWNREVIEWS 頁面 → AI生成評論 → 貼到 Google
```

**為什麼先加 LINE 再寫評論：**
- 每則評論背後都有一個可再接觸的客人
- LINE 粉絲是長期資產，評論是一次性的
- 一個動作同時餵了評論輪 + 會員輪 + 未來廣播輪 + 裂變輪
