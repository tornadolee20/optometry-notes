## Self-Correction Log

1. `rg.exe` 在目前 Windows 執行環境回傳 Access Denied，廣泛 `Get-ChildItem -Recurse` 又曾逾時。修正：改用 `git ls-files` 縮小 tracked 範圍，再以目標式 `Get-ChildItem`／`Select-String` 掃描需要的目錄。
2. 系統 `python` 不可用。修正：透過工作區依賴清單取得 bundled Python 的明確路徑；KDF validator 只用 standard library，沒有新增套件。
3. 大型 `apply_patch` 在桌面工具中曾長時間沒有輸出。修正：不重送相同 patch，先等待完成並逐檔驗證，避免重複內容。
4. 第一版 wikilink regex 無法正確解析檔名本身含 `]` 的既有卡片，validator 因而 fail。修正：既有卡連結加上 alias，parser 改為允許非終止的單一 `]`；重跑後 broken links 歸零。
5. 額外的 fail-closed 負向測試第一次把相對路徑傳進只接受 repo 絕對路徑的報錯格式化函式，測試 harness 先失敗。修正：測試輸入先 `.resolve()`，四個安全欄位的負向測試均成功拒絕錯誤資料；產品 validator 的正式 PASS 結果未受影響。
6. 批次正規化 Markdown EOF 時，shell 對 `.agents/workflows/` 的三個檔案回報拒絕存取，且 PowerShell 仍回傳整體 exit 0。修正：逐項看 stderr，不以 exit code 單獨判斷；這三個檔案原本沒有 EOF 問題，其餘明確 KDF 路徑完成正規化，之後以 `git diff --cached --check` 作最終依據。

7. A broad audit command combined quoted `git ls-files` output with `Test-Path`; Windows Git's C-style quoted Unicode paths are display data, not literal paths. The command timed out without writes. Future inventory should use targeted literal paths or `git -c core.quotepath=false -z ls-files` with NUL-safe parsing.
8. `rg.exe` again failed to launch during the Bridge audit. The audit immediately switched to scoped `Get-ChildItem` plus `Select-String`; no result was inferred from the failed search.
9. The first Markdown fence check used the broad pattern `^````, so paragraphs beginning with inline code were miscounted as fences. A strict whole-line fence pattern confirmed 66 balanced fences; future checks must match only complete fence lines.
10. Bridge preflight tried `git -c core.excludesfile=NUL status`; Git rejected `NUL` as an exclude file and then failed while inspecting an embedded submodule. No write occurred. Use normal `git status --ignore-submodules=all` and tolerate the global-ignore warning instead of overriding the exclude file.
11. A recursive search for related `AGENTS.md` files crossed large archived/sandbox trees and timed out after the relevant root result was already visible. Restrict instruction discovery to the task directories and their ancestors.
12. A PowerShell `foreach { ... } | ConvertTo-Json` inventory command was parsed as an empty pipeline element. No command body ran. Use an explicitly collected array or a small read-only Node metadata script for multi-file inventories.

## Workflow Rule Assessment

- 本次錯誤均已有現行安全原則可涵蓋，或屬單次執行環境／validator 實作細節；不需要修改 `AGENTS.md`。可重用的 KDF 規則已寫入專用 workflow、schema 與 validator，避免把專案細節擴散到全域規範。
- 13. 大型多檔 `apply_patch` 在第一個檔案後長時間未回傳，必須中止並逐檔確認；改採較小 patch，避免不確定的部分寫入與重複套用。
- 14. Root `.gitignore` 含既有非 UTF-8 位元，`apply_patch` 安全驗證拒絕更新；不要整檔轉碼，runtime 改由子目錄 `.gitignore` 隔離，transaction temp 強制清理並測試無殘留。
- 15. 並行 `apply_patch` 的 JavaScript template string 被內嵌 TypeScript backtick 截斷，呼叫在執行前失敗；並行前先移除或跳脫內嵌 backtick。
- 16. `npm install` 在 sandbox 與核准模式都未自行結束（後者持續超過 20 分鐘），但 lockfile、node_modules 與完整 build 已成功；先終止孤立安裝程序，再用 build / npm ci 驗證實際安裝狀態。
- 17. Service 第一次 build 發現三個 TypeScript narrowing/Promise path 錯誤：先 await path resolver，並把 validated optional root 存成非 optional local，之後再重跑 build。
- 18. 新 validator 首跑把既有 typed discovery relation object 與 legacy `blog-review-draft` 誤判；persisted contract 要明確兼容既有合法表示法，但 public tool input 仍維持新六平台 allowlist。
- 19. MCP adapter 第一次 build 顯示 SDK 的 `structuredContent` 需要 string index signature；將 service envelope 轉成 plain JSON object 後回傳，不放寬 tool schema。
- 20. 第一輪測試 7/12 pass；失敗揭露 fixture 外部 link stub、MCP z.any output、活鎖 stale 誤判、Windows realpath device prefix、audit raw hash 五點，逐項修正後重跑。
- 21. 最終 `npm ci --prefer-offline` 因使用者全域 npm cache 發生 `EPERM stat`；改用 package-local、Git-ignored `.npm-cache` 重跑，避免依賴不可寫的全域 cache。
