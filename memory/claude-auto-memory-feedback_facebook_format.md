文章產出完畢後，**必須自動輸出臉書手機版**，無需等待大叔提醒。

**Why:** 臉書不支援 Markdown，手機閱讀以「掃視」為主，需要特殊節奏感的純文字排版才能讓人一直往下滑。

**How to apply:** 每次執行 `/blog-post` 工作流時，在 LINE 短版之後，自動輸出 FB 版存至 `content-planning/{文章名稱}-FB版.txt`。

## 核心排版原則

- 純文字，禁用 Markdown 符號
- 一句一行，每行不超過約 18 字
- 段落間空一行，每段不超過 3 句
- 禁用列點符號（• - →），改用數字或直接分段
- 禁用「——」破折號、空洞套話、AI 感套話
- 子標題用 `◾` 開頭（小黑方塊），提供視覺錨點但不破壞純文字感

## 節奏邏輯：蔡格尼效應

每一行製造「未完成感」，讓眼睛自動往下找答案。
每行是一次小小的停頓，讀完就往下移。

## 結構

1. **鉤子（前 3 行）**：問句 / 反直覺陳述 / 數字開場，在「查看更多」截斷前攔截注意力
2. **中段**：一行一個衝擊點，層層堆疊
3. **轉折句**：「但大部分人不知道的是——」
4. **結尾**：問句邀請留言，或引導加 LINE

## 字數目標

350～500 字

## Threads 串文版

與 FB 版同步產出，存至 `content-planning/{文章名稱}-Threads版.txt`。

**差異重點**：
- 每則上限 500 字元，拆 3～5 則，標示 `【1/4】`
- 不用 `◾` 子標題，每則自成一個焦點
- 語氣更短更直接
- Hashtag 只放最後一則（3～5 個）

**串文結構**：第 1 則鉤子 → 第 2 則故事 → 第 3 則洞察 → 最後一則 CTA + Hashtag
