# Distillation Obsidian Integration

Updated: 2026-04-15

## Purpose

This workflow defines how a completed distillation should land in durable memory.

It connects the distillation pipeline to:

- skill storage
- Obsidian notes
- long-term memory
- daily notes when appropriate

## Landing Types

### Skill

Use when the output is a reusable operating asset.

Typical landing:

- skill directory
- optional Obsidian note describing the distilled asset

### Framework Note

Use when the output is reusable logic but not yet a full skill.

Typical landing:

- Obsidian knowledge note

### Workflow

Use when the output is mainly a process sequence.

Typical landing:

- workflow document

### Template

Use when the output is mainly a reusable format.

Typical landing:

- templates path

## Memory Writeback

Write to `MEMORY.md` only when the distillation creates a durable system-level lesson, rule, or architecture improvement.

Do not write to long-term memory just because a new asset exists.

## Daily Note Writeback

Use the daily note when:

- documenting what happened
- recording uncertainty
- recording failed attempts
- preserving raw chronology

## Naming Guidance

### Skill Names

- `[person]-perspective`
- `[topic]-framework`
- `[topic]-engine`

### Obsidian Notes

- `YYYYMMDD-[topic]-distillation.md`

## Output Shape

```md
## Distillation Landing
- Target:
- Output Type: skill / note / workflow / template / reference
- Primary Path:
- Secondary Paths:
- Memory Writeback: yes / no
- MOC Update: yes / no
```

## Bottom Line

A good distillation should not end as floating output.

It should land in the correct durable layer.
