# AutoDream — 自動記憶收斂引擎

> 靈感來源：Anthropic Claude Code 源碼洩漏中發現的 `AutoDream` 概念。
> 核心思路：知識庫不只是「累積」，而是要「新陳代謝」。

## 📍 觸發條件

當收到以下任一指令時啟動本工作流：
- `/auto-dream`
- 「幫我整理記憶」
- 「知識庫有沒有衝突」
- 「蒸餾最近的筆記」

---

## 🔍 Phase 1：搜尋與掃描

**你的第一步（必須）**：呼叫 `search_obsidian` 進行以下掃描：

1. **新到資料**：搜尋關鍵字 `2026` 或今年年份——找出最近新增的知識卡片。
2. **主題掃描**：根據大叔指定的主題（如：「近視」、「散光」、「SaaS」），拉出所有相關卡片。
3. **收件匣清點**：特別搜尋檔名含有「草稿」「inbox」「待整理」的筆記。

**輸出 Phase 1 快報**（告知大叔你找到了什麼，幾張卡片、大致涵蓋哪些主題）。

---

## 🧠 Phase 2：矛盾偵測

對所有拉回的 Snippets，用以下框架進行第一性原理比對：

### 矛盾偵測框架
| 類型 | 定義 | 例子 |
|------|------|------|
| **邏輯矛盾** | 兩張卡片對同一問題給出相反的建議 | 一張說「散瞳劑無副作用」、另一張說「需監測眼壓」 |
| **資料過時** | 舊知識被新的研究取代 | 舊文章用 2019 年近視盛行率，新卡片有 2024 年數據 |
| **重複冗餘** | 兩張卡片講的幾乎是同一件事 | 兩張都在說「近視控制的四大療法」 |

若發現矛盾或冗餘，**清楚列出**：
```
⚠️ 矛盾發現：
- 卡片A（YYYYMMDD-XXX）說：...
- 卡片B（YYYYMMDD-YYY）說：...
- 我的建議：保留 [卡片X] 的觀點，因為 [理由]
```

若一切正常，回報：`✅ 知識庫邏輯一致，未發現明顯矛盾。`

---

## ✍️ Phase 3：收斂寫作（僅在有矛盾時執行）

若 Phase 2 發現衝突，你必須：
1. 以你判斷最正確的觀點為主幹，整合兩邊有效的部分。
2. 撰寫一張新的「**收斂記憶卡片**」，標題格式：`[記憶收斂]-{主題名稱}`。
3. 呼叫 `create_obsidian_card`，以 `contentType: "04-知識卡片"` 寫入，標籤必須加上 `#記憶收斂`。
4. 在卡片底部寫上「已收斂來源」，列出被整合的舊卡片名稱。

---

## 💬 最終回報格式

```
🌙 AutoDream 完成報告
─────────────────────
掃描卡片：X 張
發現矛盾：Y 個
新增收斂卡：Z 張（或：無需新增）
─────────────────────
[若有矛盾] 建議大叔可以考慮在 Obsidian 中手動刪除/封存以下舊卡片：
- YYYYMMDD-XXX.md（已被收斂至新卡片）
```
