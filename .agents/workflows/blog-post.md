# 部落格文章標準產出流程 /blog-post

// turbo-all

## 適用對象
目鏡大叔（李錫彥）的 Blogger 部落格文章，所有文章須遵循此標準。

## 預先處理：Blogger 瑣碎設定自動化

為了節省手動填寫後台設定的時間，文章產生時必須在最頂端自動生成 **Blogger 發表設定區塊 (HTML 註解形式)**，讓大叔可以直接複製貼上：

## 第一步：內容撰寫（Markdown 草稿）

1. 用第一人稱「我」撰寫，語氣像「在櫃檯旁邊講故事」
2. **必須包含「5秒鉤子 (Tiered Hook Strategy)」**：開場前 3~5 秒內必須攔截注意力，嚴禁使用「大家好」等通用廢話，直接將最具衝擊力的結論、問題或故事衝突前置。
3. 必須包含以下結構區塊：
   - **開場故事**（真實案例，有畫面感）
   - **專業知識 / 數據段**（引用官方數據，標註年份與來源。⚠️ 若為學術研究，**強制附上 PMID 號碼**，大幅提升 AI 引擎信任度）
   - **行動建議**（具體、可操作，最好收成 3 點以內）
   - **作者介紹段**（含三大頭銜）
   - **CTA 區塊**（地址、電話、LINE 連結）
   - **FAQ**（4～6 題，命中家長/客群常見問題）
   - **GEO 段落首句粗體總結**：每個 H2 標題下方的「第一句話」，必須用語意完整的粗體文字 `<b>` 寫出該段的核心總結，方便 SGE 等 AI 爬蟲精準抓取段落主旨。
4. **智能內連編織 (Internal Linking)**：
   - AI 必須主動掃描 `obsidian-vault/10-歷史文章智庫/` 中的歸檔紀錄。
   - 挑選 1~2 篇與當前核心痛點（如：雙眼視覺、多焦點）高度相關的歷史文章。
   - 以「情境對話」的方式自然嵌入正文超連結（例如：「就像大叔之前在『某某文章』裡提過的...」），嚴禁使用生硬的「延伸閱讀」條列。
5. 草稿存放路徑：`content-planning/{文章名稱}.md`

## 第二步：標題審定與優化 (Title Evaluation)

如果草稿的標題尚未經過虛擬受眾測試，在轉換為 HTML 之前，必須先啟動 [標題與主題優化工作流](/title-optimizer.md)：
1. **呼叫指令**：執行 `/title-optimizer` 並提供草稿核心內容。
2. **應用結果**：後續所有 HTML（包含 `<title>`、`<h2>`、Schema）及 Obsidian 歸檔的標題，**強制使用該工作流產出的終極標題**。
3. **確認主題**：確保主標籤符合該工作流選定的「核心主題」。

## 第三步：轉換為 Blogger HTML 格式

套用以下 HTML 格式規範：

### 標籤對照
| 內容 | HTML 標籤 |
|---|---|
| 文章主標題 | `<h2 class="post-sub-title" style="font-size: 1.1em; color: #555;">` |
| 作者署名 | `<p class="post-author" style="color: #888; font-size: 0.9em;">` |
| 段落 | `<p>` |
| 分隔線 | `<hr />` |
| 章節標題 | `<h2>` |
| 引言 / 金句 | `<blockquote class="note">` |
| 粗體強調 | `<b>` |
| FAQ 問答 | `<p class="faq-item"><b>Q1：問題</b><br /> 回答內容</p>` |
| 內部雙向連結 | 草稿中的 `[[檔名\|文字]]` 轉換為 `<a href="該檔名對應的實際 URL">文字</a>` (請去 `blog-index.json` 查 URL) |
| 資料來源 | `<p class="data-source" style="color: #999; font-size: 0.8em;">（資料來源：...）</p>` |
| 主視覺圖片 | `<div class="separator">` + `<picture>` + WebP source |
| Google Maps | `<iframe>` 嵌入（固定為自己的眼鏡地址） |

### CTA 區塊（每篇文章底部必須有，H2 與引導段依主題機動調整）

**H2 標題**依文章主題動態生成：
| 文章主題 | CTA H2 |
|---------|--------|
| 兒童近視 | 📍 孩子的視力，值得被好好守護 |
| 長者視力/失智 | 📍 長輩的視力，值得被好好守護 |
| 成人/上班族 | 📍 你的視界，值得被好好對待 |
| 多焦/老花 | 📍 從容的視界，從一副對的眼鏡開始 |

**引導段（H2 下方）**：不可只寫一句問句。必須寫 **2 段**，第一段回扣文章的核心痛點場景，第二段帶出「來店裡讓大叔看一下」的行動呼籲，並自然提及文章中的專業亮點（如：對比敏感度、角膜塑型片追蹤等）。

### 作者介紹段（每篇文章必須有，最後兩段依主題機動調整）
前兩段固定不動：
```html
<p>嗨，我是<a href="https://www.uncle-glasses.net/p/about.html">目鏡大叔 - 李錫彥</a>。身為「自己的眼鏡」與「自己的驗光所」的負責人，我在視光這個行業耕耘超過 20 年。</p>

<p>除了在店裡服務大家，我也擔任<b>元培醫事科技大學企管系兼任講師</b>，並身兼<b>臺灣視光視力保健學會常務理事</b>與<b>新北市驗光師公會常務理事</b>，希望能將視力保健的觀念分享給更多人。</p>
```

後兩段**必須依照該篇文章的主題受眾，機動調整語境**：

| 文章主題 | 第三段「在意的事」 | 第四段「順了之後的願景」 |
|---------|------------------|----------------------|
| 兒童近視 | 孩子的生活怎麼過、學習有沒有變順 | 視覺穩，孩子才有本錢把注意力放在學習跟生活上 |
| 長者視力/失智 | 家裡長輩的生活品質有沒有被視覺問題拖累 | 視覺穩了，大腦才有餘裕去記住家人說的話、出門看清路上的花 |
| 成人/上班族 | 你每天盯螢幕多久、下班後眼睛還舒服嗎 | 視覺穩了，工作效率跟生活品質才能同時顧到 |
| 多焦/老花 | 你戴上去之後遠近切換順不順、會不會頭暈 | 視覺穩了，不用再低頭拿眼鏡、抬頭換眼鏡，生活自然從容 |

⚠️ **核心句型不變**：「一副好眼鏡不是讓你『忍耐』，而是讓你『順』。順了，才戴得久；戴得久，視覺才穩；視覺穩，[依主題填入願景]。」

## 第三步：SEO 與 AI 可發現性優化

### 3.1 自然植入 SEO 關鍵字（強攻 Local SEO 地區關鍵字）
實體店面極度依賴在地搜尋。在正文與標題中必須自然帶入以下「地區 + 服務」關鍵字組合（不可硬塞，約出現 2～3 次即可）：
- **核心與周邊地區**：（💡 知識點：台北大學簡稱北大，北大特區主要是由 **三峽** 與 **樹林（柑園）** 兩個地政區組成。大生活圈還會輻射到鶯歌、土城）
  例如：「三峽驗光師」、「北大特區配眼鏡推薦」、「樹林兒童近視控制」、「鶯歌驗光所」、「土城多焦鏡片」
- 其他依主題調整的長尾關鍵字（如：「散光」、「角膜塑型片推薦」等）

### 3.2 Blogger 搜尋說明（Meta Description）
在 HTML 最頂端用註解提供，大叔發布時須手動貼到 Blogger 後台右側的「搜尋說明」欄位：
```html
<!--
  2. 搜尋說明 (Meta Description)：
     [自動生成：150 字以內的點擊誘餌摘要。強制包含「地區關鍵字 (如: 三峽驗光師)」、「受眾核心痛點」與「具體解方文字」，且語氣須吸引點擊]
-->
```

### 3.3 Article JSON-LD Schema（每篇必加）
放在 HTML 最頂部（主視覺圖片之前）：
```json
{
  "@context": "https://schema.org",
  "@type": "Article",
  "headline": "文章標題",
  "description": "文章摘要",
  "image": "主視覺圖片 URL",
  "author": {
    "@type": "Person",
    "name": "李錫彥（目鏡大叔）",
    "url": "https://www.uncle-glasses.net/p/about.html",
    "jobTitle": "驗光師／自己的眼鏡負責人",
    "affiliation": [
      { "@type": "Organization", "name": "自己的眼鏡・自己的驗光所" },
      { "@type": "EducationalOrganization", "name": "元培醫事科技大學" },
      { "@type": "Organization", "name": "臺灣視光視力保健學會" },
      { "@type": "Organization", "name": "新北市驗光師公會" }
    ],
    "knowsAbout": ["請依據該篇文章主題動態生成 4~5 個高度相關的專業領域", "例如：頸肩痠痛與視覺負荷", "驗光配鏡", "視力保健"]
  },
  "publisher": {
    "@type": "Organization",
    "name": "自己的眼鏡",
    "url": "https://www.uncle-glasses.net"
  },
  "datePublished": "YYYY-MM-DDT10:00:00+08:00",
  "dateModified": "YYYY-MM-DDT10:00:00+08:00",
  // ⚠️ 日期格式規則：
  // - 必須使用完整 ISO 8601 格式含台灣時區 +08:00
  // - 時間固定填 10:00:00（不需知道實際發布時間）
  // - datePublished = 文章初次發布日
  // - dateModified  = 本次修改或發布日（兩者可相同）
  // ✅ 正確範例："2026-03-27T10:00:00+08:00"
  // ❌ 錯誤範例："2026-03-27"（缺少時間與時區）
  "keywords": ["依文章主題填入"]
}
```

### 3.4 FAQPage JSON-LD Schema（每篇必加）
放在 HTML 最底部（FAQ 內容之後）：
```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "問題文字",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "答案文字"
      }
    }
  ]
}
```

### 3.5 BreadcrumbList JSON-LD Schema（🌟 GEO 強制要求：導覽列階層）
Blogger 系統有時無法完美產出導覽列 Schema，**每篇文章必須**在 HTML 底部放置 BreadcrumbList，這是 SGE 與各大 AI 引擎抓取網站架構的絕對關鍵：
```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [{
    "@type": "ListItem",
    "position": 1,
    "name": "首頁",
    "item": "https://www.uncle-glasses.net/"
  },{
    "@type": "ListItem",
    "position": 2,
    "name": "核心標籤名稱 (如：專業視光科普)",
    "item": "https://www.uncle-glasses.net/search/label/核心標籤名稱"
  },{
    "@type": "ListItem",
    "position": 3,
    "name": "文章標題"
  }]
}
```

### 3.6 Blogger 標題特例提醒 (H1/H2)
⚠️ Blogger 的系統設定會自動將「文章標題欄位」轉為 `<h1>`，因此**文章正文內的最高層級大標必須從 `<h2>` 開始**，絕不可在 HTML 內文中使用 `<h1>`，以免造成一個頁面出現多個 H1，破壞 SEO 權重。

## 第四步：E-E-A-T 自我檢查清單

發布前用此清單逐項確認：

- [ ] **Experience**: 文章是否基於真實第一手經驗？有具體細節和情境？
- [ ] **Expertise**: 是否引用了具體數據（含年份、來源）？FAQ 是否展開專業方法名稱？
- [ ] **Authoritativeness**: 作者介紹段是否包含三大頭銜？Article Schema 是否完整？
- [ ] **Trustworthiness**: 資料來源是否標註？語氣是否「不嚇人但讓你醒」？無推銷感？
- [ ] **SEO 關鍵字**: 正文中是否自然帶入 1～2 次核心關鍵字？
- [ ] **Meta Description**: 是否已提供 Blogger 搜尋說明？
- [ ] **JTBD 一致性**: 是否已埋入「情感掌控感」與協助家長溝通的「社交話術包」？
- [ ] **雙 Schema**: Article + FAQPage JSON-LD 是否都已加入？

## 第五步：反 AI 味檢查清單 (Anti-AI Writing Check) 🛡️

為了確保文章保持大叔獨特的真人語氣，發布前嚴格檢查是否觸犯以下「8 大 AI 寫作缺陷」：

- [ ] **缺陷 1：空洞的總結句** - 結尾是否給出了具體、可執行的下一步？（例如：「明天開始試著...」而非「讓生活更美好」）
- [ ] **缺陷 2：過度使用列點符號** - 除非是步驟說明，否則優先將列點改寫為具備邏輯連貫性的短結構成段落。
- [ ] **缺陷 3：毫無長度變化的句子** - 是否有適當變化句子長度？強制要求有「單行成段」的金句，配上不超過 3 行的敘述段落。
- [ ] **缺陷 4：主詞選擇不當** - 句子主詞是否合理？（例如：重點是人還是機制？）
- [ ] **缺陷 5：資訊密度太低** - 前言是否在說廢話？請直接切入具體數字或真實痛點。
- [ ] **缺陷 6：內容太籠統** - 是否有「三峽店裡真實客訴情境（Experience）」？必須有具體的「人、事、時、地、物」。
- [ ] **缺陷 7：過度使用代名詞** - 請把多餘的「這個」、「那個」、「這些」替換為精準的名詞（例如：「跳行的困擾」而非「這些狀況」）。
- [ ] **缺陷 8：流暢但缺乏理解** - 專業術語（例如：調節痙攣、注意力機制）是否用了一個家長聽得懂的「精準比喻」來解釋？

## 第六步：產出衍生版本

### LINE 群組轉傳短版
- 約 700～800 字
- 只保留核心故事 + 數據亮點 + 行動建議 + CTA
- 用 emoji 和「━━━」分隔線排版，適合手機閱讀
- 存放路徑：`content-planning/{文章名稱}-LINE短版.txt`

### 臉書手機版（Facebook Mobile Post）
每次產出完整文章後，**自動輸出臉書版**，遵循以下規範：

**格式原則（手機閱讀優先）**：
- 純文字，不用任何 Markdown 符號
- 一句一行，每行不超過約 18 字
- 段落間空一行，每段不超過 3 句
- 禁用列點符號（• - →），改用數字或直接分段
- 禁用「——」破折號、空洞套話、AI 感金句
- 子標題用 `◾` 開頭（小黑方塊），提供視覺錨點但不破壞純文字感

**結構規範**：
1. **開頭（鉤子）**：前 3 行要在「查看更多」截斷前攔截注意力，用問句、反直覺陳述、或數字開場，絕不能以「大家好」起頭
2. **中段（節奏堆疊）**：每行一個衝擊點，利用蔡格尼效應（每行未完成感），讓讀者自然往下滑
3. **轉折句**：「但大部分人不知道的是——」或同等效果的一行
4. **結尾（行動）**：用一個問句邀請留言，或引導加 LINE

**範例節奏（參考）**：
```
[問句或反直覺開場]

[短補充]

[再一層揭示]

[關鍵事實，一行一個]
[關鍵事實]
[關鍵事實]

但大部分人不知道的是——

[核心洞察]

[你的孩子/你的眼睛] 最近一次 [相關行為] 是什麼時候？
```

- 字數目標：350～500 字
- 存放路徑：`content-planning/{文章名稱}-FB版.txt`

### Threads 串文版
每次產出完整文章後，**自動輸出 Threads 版**，遵循以下規範：

**與 FB 版的關鍵差異**：
- 每則上限 500 字元，拆成 3～5 則串文
- 用 `【1/4】【2/4】` 標示串文順序（依實際則數調整）
- 不用 `◾` 子標題（每則本身就是一個焦點）
- 語氣更短、更直接，像說話不像寫文章
- Hashtag 只放在最後一則結尾（3～5 個）
- **同樣遵守手機排版原則**：一句一行、每行不超過約 18 字、長句必須拆開

**串文結構**：
- **第 1 則（鉤子）**：反直覺觀點或核心衝突，拉人繼續看
- **第 2 則（故事）**：真實案例，帶入情境與情緒
- **第 3 則（洞察）**：專業知識點，一段一個概念
- **最後一則（CTA）**：行動呼籲 + 問句邀留言 + Hashtag

- 存放路徑：`content-planning/{文章名稱}-Threads版.txt`
