# 部落格文章標準產出流程 /blog-post

// turbo-all

## 適用對象
目鏡大叔（李錫彥）的 Blogger 部落格文章，所有文章須遵循此標準。

---

## 預先處理：Blogger 瑣碎設定自動化

為了節省手動填寫後台設定的時間，文章產生時必須在最頂端自動生成 **Blogger 發表設定區塊 (HTML 註解形式)**，供系統自動抓取或手動對照：

```html
<!--
  Blogger 後台設定指引 (請完整複製到對應欄位)：

  1. 永久連結 (自訂 URL)：
     [自動生成：根據文章主題生成英文短網址，如 child-myopia-control]

  2. 搜尋說明 (Meta Description)：
     [自動生成：150 字以內的點擊誘餌摘要。強制包含「地區關鍵字 (如: 三峽驗光師)」、「受眾核心痛點」與「具體解方文字」，且語氣須吸引點擊]

  3. 文章標籤 (Labels)：
     [自動生成：**必須**從以下六大核心主題中挑選 1 個最符合的]
     - 驗光故事
     - 兒童視力保健 (⚠️ 注意：不可簡寫為兒童視力)
     - 專業視光科普 (⚠️ 注意：不可簡寫為視光科普)
     - 找回從容
     - 經營思考
     - 大叔的視界觀
     [搭配：再依據文章內容，補上 1~3 個具體的 SEO 次要關鍵字標籤，例如：多焦鏡片、白內障、近視控制]

  4. 首圖圖片替代文字 (Alt Text)：
     [自動生成：描述首圖情境的文字，並自然融入 SEO 關鍵字]

  5. 首圖英文檔名建議 (Image Filename)：
     [自動生成：SEO 友善的英文小寫檔名，單字間用連字號，如 vision-dementia-risk-glasses.jpg]

  6. 地點 (Location)：
     [自動生成：預設為「自己的眼鏡」，或依據文章主要提及之地點如「新北市三峽區」]

  7. 文章關鍵字 (SEO Keywords)：
     [自動生成：將 Schema 裡的 keywords 陣列列出，方便大叔發布時當作 Hashtag 或自我檢核使用，例如：三峽驗光師, 兒童近視控制, 對比敏感度]
-->
```

## 第一步：內容撰寫（Markdown 草稿）

1. 用第一人稱「我」撰寫，語氣像「在櫃檯旁邊講故事」
2. **必須包含「5秒鉤子 (Tiered Hook Strategy)」**：開場前 3~5 秒內必須攔截注意力，嚴禁使用「大家好」等通用廢話，直接將最具衝擊力的結論、問題或故事衝突前置。
3. 必須包含以下結構區塊：
   - **開場故事**（真實案例，有畫面感）
   - **專業知識 / 數據段**（引用官方數據，標註年份與來源。⚠️ 若為學術研究，**強制附上 PMID 號碼**，大幅提升 AI 引擎信任度）
   - **行動建議**（具體、可操作，最好收成 3 點以內）
   - **作者介紹段**（含三大頭銜）
   - **CTA 區塊**（地址、電話、LINE 連結）
   - **FAQ**（4～6 題，命中家長/客群常見問題）
   - **GEO 段落首句粗體總結**：每個 H2 標題下方的「第一句話」，必須用語意完整的粗體文字 `<b>` 寫出該段的核心總結，方便 SGE 等 AI 爬蟲精準抓取段落主旨。
4. **智能內連編織 (Internal Linking)**：
   - AI 必須主動掃描 `obsidian-vault/10-歷史文章智庫/` 中的歸檔紀錄。
   - 挑選 1~2 篇與當前核心痛點（如：雙眼視覺、多焦點）高度相關的歷史文章。
   - 以「情境對話」的方式自然嵌入正文超連結（例如：「就像大叔之前在『某某文章』裡提過的...」），嚴禁使用生硬的「延伸閱讀」條列。
5. 草稿存放路徑：`content-planning/{文章名稱}.md`

---

## 第二步：標題審定與優化 (Title Evaluation)

如果草稿的標題尚未經過虛擬受眾測試，在轉換為 HTML 之前，必須先啟動 [標題與主題優化工作流](/title-optimizer.md)：
1. **呼叫指令**：執行 `/title-optimizer` 並提供草稿核心內容。
2. **應用結果**：後續所有 HTML（包含 `<title>`、`<h2>`、Schema）及 Obsidian 歸檔的標題，**強制使用該工作流產出的終極標題**。
3. **確認主題**：確保主標籤符合該工作流選定的「核心主題」。

---

## 第三步：轉換為 Blogger HTML 格式與自動上稿 🤖

### 3.1 轉換 HTML
將文章轉為 Blogger HTML 格式（存於 `content-planning/{文章名稱}.html`）。

### 3.2 【全自動化】Playwright 背景 Blogger 自動發布與欄位填寫

生成 HTML 後，自動啟動 Playwright 腳本，開啟 Blogger 後台完成全自動上稿：

```bash
python scripts/social-research/auto_blogger_publisher.py \
  --title "[文章標題]" \
  --file "content-planning/[文章檔名].html" \
  --slug "[英文短網址]" \
  --labels "[標籤1, 標籤2]" \
  --desc "[搜尋描述摘要]"
```

* **此腳本會自動完成**：
  1. 繼承本地 Chrome 的 Blogger 登入狀態。
  2. 自動輸入文章標題與 HTML 全套代碼（含 Schema）。
  3. 自動填寫**英文網址 (Permalink)**、**標籤 (Labels)** 與 **搜尋描述 (Search Description)**。
  4. 自動點擊「儲存草稿」供前輩隨時做最後確認或發布。

## 第四步：E-E-A-T 自我檢查清單

發布前用此清單逐項確認：

- [ ] **Experience**: 文章是否基於真實第一手經驗？有具體細節和情境？
- [ ] **Expertise**: 是否引用了具體數據（含年份、來源）？FAQ 是否展開專業方法名稱？
- [ ] **Authoritativeness**: 作者介紹段是否包含三大頭銜？Article Schema 是否完整？
- [ ] **Trustworthiness**: 資料來源是否標註？語氣是否「不嚇人但讓你醒」？無推銷感？
- [ ] **SEO 關鍵字**: 正文中是否自然帶入 1～2 次核心關鍵字？
- [ ] **Meta Description**: 是否已提供 Blogger 搜尋說明？
- [ ] **JTBD 一致性**: 是否已埋入「情感掌控感」與協助家長溝通的「社交話術包」？
- [ ] **雙 Schema**: Article + FAQPage JSON-LD 是否都已加入？

---

## 第五步：反 AI 味檢查清單 (Anti-AI Writing Check) 🛡️

- [ ] **缺陷 1：空洞的總結句** - 結尾是否給出了具體、可執行的下一步？
- [ ] **缺陷 2：過度使用列點符號** - 優先將列點改寫為邏輯連貫短段落。
- [ ] **缺陷 3：毫無長度變化的句子** - 有「單行成段」的金句與短段落。
- [ ] **缺陷 4：資訊密度太低** - 前言切入具體數字或真實痛點。
- [ ] **缺陷 5：內容太籠統** - 有「三峽店裡真實客訴情境（Experience）」。

2. 提煉金句與解方，自動附加至 `obsidian-vault/04-知識卡片/目鏡大叔金句庫.md`。

## 檔案命名規範

| 類型 | 命名格式 | 範例 |
|---|---|---|
| Markdown 草稿 | `{文章名稱}.md` | `遮雨棚下的一堂課-完整版.md` |
| Blogger HTML | `{文章名稱}.html` | `遮雨棚下的一堂課-完整版.html` |
| LINE 短版 | `{文章名稱}-LINE短版.txt` | `遮雨棚下的一堂課-LINE短版.txt` |
| Obsidian 智庫檔 | `YYYYMMDD-{文章名稱}.md` | `20260305-遮雨棚下的一堂課.md` |

所有草稿與發布用檔案統一存放在 `content-planning/` 資料夾。智庫檔則直接存入 `obsidian-vault/10-歷史文章智庫/`。
