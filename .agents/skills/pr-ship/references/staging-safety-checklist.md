# Staging Safety Checklist

在執行 `git add` 前逐項確認：

- [ ] 已取得精確的預期變更檔案清單（不是「大概這幾個」）
- [ ] `git status` 列出的變更**恰好**等於預期清單，沒有多、沒有少
- [ ] 沒有任何本機專屬設定檔（編輯器本機設定、個人執行環境設定、本機
      憑證/密鑰檔）出現在待 stage 清單中
- [ ] 若清單中包含平常會被 `.gitignore` 排除的路徑，已確認這是本次任務
      刻意要追蹤的例外，而非誤觸
- [ ] 沒有使用 `git add .` 或 `git add -A` 等寬鬆語法
- [ ] stage 完成後重新 `git status` 核對，確認結果與清單一致

## 常見誤觸來源

- 編輯器/IDE 自動產生的本機設定檔
- 本機執行腳本或啟動設定（僅供個人開發環境使用）
- 暫存或快取檔案（若專案的 `.gitignore` 尚未涵蓋到，容易被寬鬆的 `add`
  指令誤收）
- 上一輪任務遺留、與本次出貨無關的未提交變更
