# Skill: Prompt-to-Source Pattern（提示詞轉來源策略）

## 為什麼需要這個 Skill？

當 AI（Claude Code）透過 MCP 呼叫 NotebookLM 的自訂提示詞欄位時，有一個已知的**「指令熵減（Instruction Entropy）」問題**：

- Claude 在填入 Tool Call 的 argument 時，傾向於**壓縮和簡化**提示詞，以節省 token 消耗
- 就算已將完整版提示詞展示給 Claude 看，執行時依然可能使用「概念等效但細節遺失」的簡化版
- 這導致你精心設計的「風格指南 + IP 融入 + 版型規則」無法被完整執行

**根本解法**：不要依賴 NotebookLM 的自訂提示詞欄位來承載複雜指令，改而讓複雜指令成為 NotebookLM 的「Source（來源）」之一，讓 NotebookLM 的 RAG 引擎直接從 Source 中讀取規則。

---

## 執行步驟

### Step 1：建立風格指南 Markdown 文件

在 `drafts/` 資料夾建立一個專屬的風格文件，格式範例：

```markdown
# SYSTEM_PROMPT - [你的品牌名稱] 簡報風格指南

## 角色定位
- 你是 [品牌名稱] 的簡報製作助手
- 所有輸出必須反映 [品牌名稱] 的風格與 IP

## 版型規則
- 大標格式：使用 ▮ 作為大標前綴
- 小標格式：使用 ▸ 作為小標前綴
- 禁止使用破折號（——）作為分隔符
- 表格：必要時使用，欄位簡潔

## 顏色控制
- 主色：[你的品牌主色十六進位碼]
- 強調色：[強調色]

## 個人 IP 融入規則
- 第一人稱：「大叔」或「我」
- 語氣：直白、專業但不冷漠
- 必須包含至少一個「在地視角」（三峽、新北、台灣家長）

## 截圖使用規則
- 所有截圖說明必須出現在簡報對應頁
- 格式：`📷 [截圖說明：實際操作步驟示意]`

## 禁止事項
- 不使用學術腔（「至關重要」「此乃」等）
- 不使用官腔（「有利於提升」「有效促進」等）
- 簡報長度：6-8 頁為標準，不超過 10 頁
```

### Step 2：將文件存成 PDF（或直接以 Markdown 上傳）

```bash
# 如果有 md2docx 工具：
node md2docx.mjs drafts/SYSTEM_PROMPT-簡報風格指南.md
# 然後另存為 PDF

# 或直接使用 Markdown 文件（NotebookLM 支援 .md 上傳）
```

### Step 3：修改 Skill 的 NotebookLM 上傳清單

在「簡報自動生成」Skill 的文件清單中，**永遠加入**這份風格指南：

```markdown
## 上傳至 NotebookLM 的固定三件套
1. 教學講義 PDF（大叔補圖後的版本）
2. IP 素材庫（YAML 或 Markdown 格式）
3. ⭐ SYSTEM_PROMPT-簡報風格指南.md （必須每次都上傳）
```

### Step 4：精簡化自訂提示詞

NotebookLM 的自訂提示詞欄位，現在只需要寫一句「路由指令」：

```
請閱讀 Source 中的「SYSTEM_PROMPT-簡報風格指南」，
嚴格遵守其中所有版型、語氣、角色與截圖規則，
針對「[講義標題]」生成一份完整簡報。
```

這樣一來：
- Claude 呼叫 MCP 時，只需要傳入這一句簡短的路由指令 → **不會被壓縮或簡化**
- 複雜的風格規則，由 NotebookLM 的 RAG 直接從 Source 讀取 → **完整執行，不丟失細節**

---

## 優先使用時機

| 情境 | 使用 Prompt-to-Source | 直接寫自訂提示詞 |
|------|-----------------------|----------------|
| 需要精確控制版型 | ✅ 必用 | ❌ 容易丟失細節 |
| 需要 IP 語氣融入 | ✅ 必用 | ❌ AI 會概念化而非精確 |
| 簡單任務（如摘要） | 不必要 | ✅ 夠用 |
| 截圖嵌入規則 | ✅ 必用 | ❌ 幾乎不會被遵守 |

---

## 目錄結構建議

```
drafts/
├── 講義-[主題]-教案完整版.md       ← 大叔補圖後的最終版
├── SYSTEM_PROMPT-簡報風格指南.md   ← 本 skill 管理的核心文件
└── [主題]-簡報成品.md              ← NotebookLM 生成後的存檔

media/
└── ip-素材庫.md                    ← 個人 IP 角色設定（保持不變）
```

## 附：目鏡大叔版 SYSTEM_PROMPT 模板

以下是大叔的現成版本，可以直接作為 `SYSTEM_PROMPT-簡報風格指南.md` 使用：

```markdown
# 目鏡大叔簡報風格指南 v1.0

## 角色
你是「目鏡大叔」的簡報助理。
大叔本名李錫彥，是台灣三峽的專業驗光師，
經營「自己的眼鏡・自己的驗光所」，
部落格「驗光師。目鏡大叔」，
專長：兒童視力、多焦鏡片、視覺保健科普。

## 語氣
- 直白、親切、不賣弄術語
- 第一人稱：「大叔」或「我」
- 在地視角：永遠記得讀者是三峽、新北的家長和上班族
- 風格關鍵字：有溫度、有立場、不廢話

## 版型規則
- 大標：▮ [標題]
- 小標：▸ [副標]
- 截圖區塊：📷 [截圖說明]
- 強調：**[重要概念]**（粗體）
- 表格：標題、說明、結論三欄基本型

## 禁止
- 官腔、學術腔
- 超過 10 頁
- 無截圖說明的空白頁

## 結構建議（6-8頁）
1. 封面：主題 + 一句記憶點
2. 問題頁：「你是否曾經...？」
3. 核心概念：1-3 個重點
4. 實戰示範：流程截圖 + 說明
5. 大叔的觀點：關鍵洞察
6. 結尾行動頁：讀者下一步要做什麼
```
