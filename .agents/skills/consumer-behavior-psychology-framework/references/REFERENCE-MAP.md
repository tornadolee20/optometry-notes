# REFERENCE-MAP.md

Updated: 2026-04-15

## Purpose

This map helps the system load the smallest useful support reference for the current consumer-behavior task.

Do not load the whole reference stack by default.

## Default Reference

Use first:

- `core-models.md`

This is the base layer for most cases.

## When To Load Additional References

### If the problem is mainly:

- hesitation
- confusion
- delay
- option overload
- unclear commitment

load:

- `friction-patterns.md`

### If the problem is mainly:

- explanation quality
- message framing
- trust-building wording
- converting technical features into human value

load:

- `framing-moves.md`

### If the task is specifically about:

- lens upgrade hesitation
- multifocal anxiety
- myopia-control explanation
- family decision dynamics
- price objection in trusted retail

load:

- `optometry-use-cases.md`

## Minimal Loading Rule

Typical use should be:

1. `core-models.md`
2. one additional focused reference only if needed

## Bottom Line

This skill should stay easy to route and easy to compose.

The reference stack exists to sharpen diagnosis, not to bloat invocation.
