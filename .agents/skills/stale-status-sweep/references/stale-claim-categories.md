# Stale Claim Categories — 判斷指引

## 1. 真正過時

判斷依據：現況證據（見 engineering-principles A 節的證據層級）直接與聲明矛盾，
且聲明沒有時間標記讓讀者知道這是舊資訊。

處理：更新為現況描述，若原句仍有參考價值（例如記錄了曾經的決策脈絡），改為
`[Historical]` 保留而非直接刪除。

## 2. 正確的否定句

判斷依據：句子語意是「目前不支援 / 尚未實作 / 目前不成立」，且這個否定判斷
在現況下仍然正確。

常見誤判：因為句子帶有「不」「尚未」「無法」等字詞，被關鍵詞掃描命中，卻被
誤認為「負面 = 過時」而錯誤修改。

處理：原樣保留。

## 3. 歷史紀錄

判斷依據：描述過去某個時間點的事實或決策，本身沒有錯誤，只是不代表現在。

處理：加上時間標記或 `[Historical]` 前綴，不刪除內容本身。

## 4. 尚未確認

判斷依據：本輪擁有的證據不足以判斷真偽（例如需要人類 owner 才知道的營運
決定、外部合作狀態）。

處理：保留原句，加上明確的「待確認」標記，並記錄需要向誰確認。

## 5. 被 superseded 的狀態

判斷依據：聲明在當時是對的，後來有更新的聲明取代它，但兩者都有保留價值
（例如呈現決策演變過程）。

處理：新舊並存，用時間順序或版本標記清楚呈現「這是後來的決定，取代了上面
那句」，而非直接覆蓋讓舊決策的脈絡消失。

## 6. 仍為 active blocker

判斷依據：聲明描述一個目前仍然成立、尚未解除的阻塞狀態。

處理：原樣保留，即使文件其他部分看起來很舊，這一句不能被「順手」一起清掉。

## 分類時的通用檢查

- 每筆分類都要能回答「我是根據哪個現況證據做出這個判斷的？」
- 若答不出來、只是「感覺應該是這樣」，該筆應歸入「尚未確認」，而不是勉強
  分到其他類別。
