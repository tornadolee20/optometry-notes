# Post-Merge Verification

合併完成後，逐項確認：

- [ ] Checkout base 分支，pull 最新狀態
- [ ] `git rev-parse HEAD`（base 分支）對照合併產生的 commit SHA，確認
      base 分支確實包含本次變更
- [ ] 工作區乾淨，僅剩本機專屬未追蹤檔案（不應有非預期的殘留變更）
- [ ] 其他不相關的 PR/分支狀態與合併前一致，沒有被本次操作意外影響
- [ ] 若 owner 授權刪除來源分支，確認刪除的是正確的分支（核對分支名稱
      與剛合併的 PR head 一致）；若未授權，保留分支不刪除
- [ ] 最終報告中明確寫出「merged 不等於 deployed」，不將本次合併結果
      描述為已上線或已部署

## 若核對失敗

- base 分支 HEAD 不包含預期變更：停止並回報，可能是 pull 失敗或合併本身
  有問題，不自行重試合併。
- 工作區出現非預期殘留：先確認是否為合併過程正常產生的暫存物，若無法
  確認來源，停止並回報，不自行清除。
- 其他 PR/分支受到影響：立即停止後續動作（例如刪除分支），完整回報受
  影響範圍，交由 owner 決定處理方式。
