# Stale State Checklist（盤點時的過時聲明標記，不做修改）

在「過時聲明掃描」步驟中，逐項確認：

- [ ] 已針對每份狀態文件，至少檢查過其中的狀態類欄位（已完成/進行中/阻塞點）
- [ ] 每個「已完成」聲明都嘗試對照過至少一層第 1-4 層證據
- [ ] 每個發現的矛盾都記錄了「文件怎麼說」與「證據怎麼顯示」兩邊
- [ ] 沒有對任何文件內容進行修改——本 Skill 只標記，不動手改
- [ ] 標記出的候選過時聲明已整理成清單，可直接交給 `stale-status-sweep` 使用
- [ ] 對於無法判斷真偽的聲明，標記為「未驗證」而非猜測後歸類

## 與 stale-status-sweep 六種分類的對應

本 Skill 的「標記」階段不需要做到 `stale-status-sweep` 那樣完整的六種分類，
但可以在報告中初步標註傾向，供後續處理時參考（最終分類仍由
`stale-status-sweep` 執行）：

- 明顯與證據矛盾 → 可能是「真正過時」
- 帶有否定語氣但仍與現況相符 → 提醒後續處理者這可能是「正確的否定句」，
  不要誤判
- 描述過去時間點的事 → 可能是「歷史紀錄」
- 涉及只有 owner 才知道的事 → 「尚未確認」
- 有更新的說法但舊說法還留著 → 可能是「被 superseded」
- 仍然成立的阻塞描述 → 「仍為 active blocker」，明確提醒不要被誤刪

## 常見誤區

- 把「盤點時發現的過時聲明」直接動手改掉——這超出本 Skill 的職責邊界，
  應該停在「標記」，交給 `stale-status-sweep` 處理實際修改。
- 只看文件最上面幾行就下結論，沒有讀完整份文件裡所有狀態類欄位。
- 把「本輪沒空核對」的項目直接跳過不記錄，而不是明確標成「未驗證」。
