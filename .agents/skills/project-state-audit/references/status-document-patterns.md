# Status Document Patterns

不同專案對「長期狀態文件」的命名與結構不同，本檔列出常見模式，供搜尋時參考，
**不假設任一命名是固定存在的**。

## 常見檔名模式（依專案而定，需實際確認是否存在）

- 任務/進度追蹤類：狀態追蹤文件（可能命名為進度紀錄、任務狀態、當前狀態等）
- 決策紀錄類：記錄「為什麼這樣決定」的文件，可能包含日期、決策內容、放棄的
  替代方案、影響範圍
- 交接類：handoff 文件，通常包含「目前分支/commit」「已完成範圍」「變更
  檔案」「證據」「阻塞點」「下一步」「禁止事項」等欄位
- 專案總覽類：README、路線圖、發版說明
- Agent/AI 協作規範類：給 AI 助理看的協作規則文件（可能命名為協作指南、
  Agent 規範等）

## 常見建議記錄欄位（供比對文件是否完整，不代表必須存在）

**進度/狀態類文件常見欄位**：
- 目前目標
- 目前範圍 / 分支
- 已完成
- 進行中
- 阻塞點
- 驗證指令與最近一次結果
- 下一步

**決策紀錄類文件常見欄位**：
- 日期
- 決策內容
- 為什麼這樣決定
- 放棄了什麼方案
- 影響範圍

**Handoff 類文件常見欄位**：
- Branch / commit
- 已完成範圍
- 變更檔案
- 證據（附層級）
- 阻塞點
- 明確下一步
- 禁止事項
- Source of truth 指向

## 搜尋建議

- 先用檔名關鍵詞搜尋（狀態、進度、決策、handoff、交接、README、roadmap 等
  詞彙，含中英文變體），列出候選清單。
- 對候選清單逐一確認是否為「長期維護、會被後續讀者當作事實依據」的文件，
  排除純粹的模板/範例檔。
- 若找不到任何符合模式的文件，如實記錄「未找到狀態文件」，不要假設它一定
  存在於某個路徑。
