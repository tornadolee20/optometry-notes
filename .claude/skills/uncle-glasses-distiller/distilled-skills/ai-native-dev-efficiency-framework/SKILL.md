# AI-Native 開發效率框架

## 何時使用

當使用者在問這類問題時，用這個 skill：
- 怎麼提升寫程式效率，但不要越快越亂
- 怎麼降低開發摩擦
- 該先做什麼
- 哪些地方可能過度工程化
- 怎麼把 AI 用對，而不是用得很爽但失控
- 怎麼設計一套可長可久的個人開發 workflow

特別適合這幾種使用者狀態：
- 同時開很多平行支線
- 把工程、寫作、研究、知識整理混在一起做
- 用 AI 快速打原型
- 卡在「要先架構好」還是「先做出來」之間

## 核心命題

開發效率，不是「每小時寫更多 code」。

它其實是五件事的乘積：
1. 先選對問題
2. 縮短從想法到證據的距離
3. 拿掉不必要的抽象
4. 把關鍵判斷留在人手上
5. 記下未來自己不該再重打一次的仗

## 三個來源層

### Karpathy 層

Karpathy 提供的是：
- 極短回饋迴路
- AI 是放大器，不是神諭
- 先做原型，早點看到真實世界反應
- 比起理論優雅，更重視可觀測性
- 對模型鋸齒行為的實戰警覺

可以問：
- 最小可跑切片是什麼
- 哪些東西我可以直接觀測，而不是腦補
- 哪些地方適合讓 AI 幫我打草稿、探路、壓縮成本
- 哪些地方如果相信 AI 太多會出事

### Carmack 層

Carmack 提供的是：
- 直接性高於儀式感
- 對不必要抽象的懷疑
- 對可執行系統的偏好
- 先簡化系統，再談系統內部優化
- 盯住真正瓶頸，而不是流行瓶頸

可以問：
- 這一層是真的在解重複問題，還是只讓我感覺自己很有架構
- 能不能先在一個檔案裡驗證，而不是先做框架
- 我現在在繳什麼複雜度稅
- 眼前真正的瓶頸到底是什麼

### Paul Graham 層

Paul Graham 提供的是：
- 價值選擇先於速度
- maker 時間保護
- 用迭代發現問題，而不是假裝一開始就很確定
- 寫作作為思考工具
- 對低價值但看起來厲害的工作的警覺

可以問：
- 這件事如果成功，哪個真實摩擦會消失
- 這是核心工作，還是安慰性工作
- 我是在創造證據，還是在延長規劃
- 我是在寫清楚問題，還是在延後決定

## 七條原則

### 1. 先縮小，再開始

把問題縮到今天就能產生證據。

好訊號：
- 今天能跑
- 今天能看到輸出
- 壞掉了也容易看懂
- 修正成本低

壞訊號：
- 我得先把底層搭好
- 等框架起來就會快很多
- 這之後會省時間，但現在沒有近端證據

### 2. 提前懷疑抽象

抽象是有罪推定，先證明自己必要再說。

優先：
- 一個 script 先於一個 subsystem
- 一條具體路徑先於通用介面
- 一次手動跑通先於全自動化
- 一個真瓶頸先於五個假想未來問題

### 3. 把 AI 當外骨骼

AI 應該延伸你的能力，不是取代你的判斷。

適合交給 AI 的角色：
- 第一版草稿產生器
- 探路夥伴
- 重複轉換工
- 測試案例發想器
- 長上下文摘要器

人類必須自己掌握的角色：
- 品味
- 取捨
- 驗收標準
- 風險判斷
- 決定什麼才重要

### 4. 優化 loop time，不要只優化規劃感

最好的 workflow，是你從變更走到證據最快的 workflow。

優先：
- 小 patch
- 小測試
- 短 debug loop
- 可回退步驟
- 看得見的輸出

避免：
- 沒 checkpoint 的大改
- 同時改太多架構層
- 第一次接觸現實之前就規劃很久

### 5. 先保護價值判斷

不要把自己訓練成很會做低價值工作的人。

開始前先問：
- 這件事如果成功，哪個痛點消失
- 誰會立刻受益
- 如果我現在不做，會怎樣
- 這是核心，還是裝飾

### 6. 保留手感

不要把直覺整包外包給工具、prompt 或流程。

保留直接接觸：
- debug
- 看輸出
- 自己打第一版
- 察覺哪裡怪怪的

流程應該放大直覺，不是蓋掉直覺。

### 7. 記決策，不只記活動

有用的筆記應該留下：
- bottleneck 是什麼
- 哪個假設失敗了
- 哪個模式有效
- 下次遇到同型問題，第一步做什麼

沒什麼價值的筆記，只會留下時間順序。

## 快速診斷

當使用者描述 workflow 問題時，先用這五題切：

1. 最小可測版本是什麼？
2. 真瓶頸在哪，哪些只是儀式感？
3. 哪些判斷一定要留在人手上？
4. 哪一步可以在一個工作時段內產生可觀測證據？
5. 哪些工作看起來很努力，其實低價值？

## 建議回覆順序

套用這個 skill 時，盡量照這個順序輸出：

1. 真正的 bottleneck
2. 被違反的是哪條原則
3. 最小下一步
4. 什麼該先停
5. AI 應該做什麼，不該做什麼

## 預設語氣

語氣要是：
- 直接的
- 實戰的
- 不裝腔，但支持使用者
- 對假進度和假高級感過敏
- 聚焦在證據、槓桿與前進感

可多用這種短句：
- 先縮小
- 先跑最小那個
- 不要太早繳架構稅
- 判斷權留在人手上
- 不要高效率做錯事

## 一句話總結

這套框架的核心就是：

做最小、最快能產生證據的那一步，把所有沒在付租金的層拿掉，讓 AI 幫你加速執行但不要接管判斷，並把時間保留給真正能消除摩擦的工作，而不是那些看起來很厲害、其實沒什麼價值的忙碌。
